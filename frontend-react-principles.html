TL;DR

  • Providers wrap outside in. Each may use only those outside it.
  • Atoms never fetch. Pages own data and routing.
  • Every design value is a token, and every theme defines every token.
  • Give each kind of state its lowest owner. Cache server state; never copy it.
  • One API client. For sensitive apps, keep tokens out of the browser.

D2 Component design and Atomic Design

D3 Design tokens and theming

P1 corePracticeLesson

Components use tokens only. Themes switch attributes on <html>, so CSS re-themes without a render.

Rules that held

  • Every token in every theme
  • No raw colours in components
  • Overrides load last
  • Motion uses duration tokens

Traps

  • A pre-paint default unlike the app default flashes
  • var() cannot reach an SVG data URI
  • A missing token fails in one theme only

Store tokens in the DTCG format, stable since version 2025.10.

Exercise
Add one token in every theme and brightness.
Check
Why can a CSS variable not colour an SVG in a data URI?

D7 Auth in the browser

P1 corePracticeLesson

Three patterns, most secure first. RFC 10017

Backend for frontend

The server holds the tokens. The browser gets an HttpOnly cookie. Recommended for business apps.

Token-mediating backend

The server gets tokens and hands the access token to the browser.

Browser-only client

The browser holds every token. PKCE is mandatory; refresh tokens rotate.

The skipped state check

"Compare if both values exist" is skipped when the stored one is missing. Reject the callback instead.

Refresh on demand before expiry, because background tabs throttle timers.

Exercise
Walk a PKCE redirect in dev tools and name each parameter.
Check

D8 Conversational and streaming UI

P2 depthLessonPractice

Make a slow, fallible model feel responsive and safe.

  1. Stream Users can type ahead into a serial queue.
  2. Show progress Staged labels on the client, not invented thoughts.
  3. Skip the model Greetings and help need no call.
  4. Confirm actions The model proposes; the user approves; the normal API runs.
  5. Announce politely aria-live="polite" for streamed text.
  • Only an explicit "feature disabled" error switches the UI mode. A blip shows a retry.
  • One chat surface. Users shown two did not know which one could act.

D11 Testing the frontend

P1 corePracticeLesson

Test the way users use the page. Query by role first, test id last.

  1. getByRole First choice.
  2. getByLabelText Form fields.
  3. getByText Visible text.

Mock service modules, not fetch. No empty act(). Smoke-test the deployed app.
