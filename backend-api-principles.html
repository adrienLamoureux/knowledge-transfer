TL;DR

  • Middleware is an ordered chain. The order is the security model.
  • Build every dependency once, in one place, and pass it in.
  • Write the contract down: one error shape, pagination and idempotency from version one.
  • Long work is a job. Record intent before you act.
  • Name a pattern only when its trigger appears.

C1 Request pipeline and middleware

P1 corePracticeNotesLesson

Each step handles the request, passes it on, or rejects it. Order matters.

  • Express error middleware takes (err, req, res, next) and goes last. Express docs
  • Never return error.message in a 500. Log the detail; return a generic message and a correlation id.
Exercise
Add a guarded admin route. Test 401 when anonymous and 403 when not admin.
Check
Why must the admin check come after the user check?

C2 Composition root and dependency injection

P1 corePracticeLesson

One place, close to the entry point, builds everything. Modules receive what they need.

  • Modules never import a concrete client themselves.
  • Allow one mode switch at most, and branch on it in the root only.
  • A big flat deps object is fine. Keep a revisit trigger instead of restructuring early.
Exercise
Add a client through the root, with a test that passes a fake.
Check
Why is this easier to test than import-time singletons?

C3 Module structure and file size

P1 coreLesson

One router factory per feature, one hub that mounts them, and a length cap in CI.

Gains

  • Namespaces stay apart
  • Each router testable alone
  • The mount map reads like a contents page

Watch

  • A changed mount prefix breaks clients silently
  • One file grew to thousands of lines before a cap
Exercise
Split one long route file by sub-domain.
Check
What does a file-length cap prevent, and what can it cost?

Shapes are contracts. Decide the hard parts in version one.

C6 Write-ahead logging and durable work

P2 depthNotesPractice

Record the intent first, then act. One extra write buys replay after a crash.

Outbox

The message is stored in the same transaction as the change. A relay publishes it.

Persist first

Write the job row before the provider call.

Checkpoints

A failure at step 7 does not re-pay for steps 1–6.

Snapshots

A bad result is rolled back, not only overwritten.

Replay means duplicates

A relay may publish twice, so every consumer must be idempotent. microservices.io

Exercise
Draw a crash at each step of one long operation. Say what survives.
Check
Why write the job row before the provider call?

C7 OOP and SOLID

P2 depthNotesLesson

Each letter prevents one smell. Name the smell, then the letter.

S
A class that both fetches and formats.
O
A growing if chain; use a registry.
L
A subclass that raises on an inherited method.
I
One large protocol instead of small ones.
D
Code that builds its own dependencies; inject them.

Prefer composition. No magic numbers. One list of allowed values, not one per side.

C9 Class and domain design

P2 depthNotes

Six steps, in order, for any class you design.

  1. Nouns Name them and their lifecycles.
  2. Boundary Keep the domain free of SDK imports.
  3. Seam Where things vary, define a protocol.
  4. Invariants Enforce them in the constructor.
  5. Immutable By default.
  6. Test Say how you would test it.

C10 Configuration and environments

P1 corePracticeLesson

Could you publish the code today without leaking a credential? Twelve-factor

  • Validate config at startup and fail fast.
  • One build artefact for every environment. Browser config holds no secrets.
  • Gate dev-only paths on the server's mode, never on a client header.
  • Flags may fail open. Identity checks never do.

C11 Testing the backend

P1 corePracticeLesson

Many unit tests, few end-to-end tests, and fakes that check the call shape.

Hundreds of green tests, a dead feature

A helper took one options object. Callers passed positional arguments and got an empty list. The fakes accepted any call, so nothing failed.

  • Inject hand-made fakes through the composition root.
  • Fake only the slow or paid edge; keep the real loop.
  • Add contract tests between services. Test pyramid
Exercise
Write a fake that would have caught the wrong-shaped call.
Check
Why did hundreds of green tests not catch it?

C12 Serverless specifics

P2 depthNotesLesson

Cheap when idle, constrained when busy. Know the limits.

  • Request-billed CPU means waiting on a third party costs money.
  • A short Prefer: wait plus polling beats one long call.
  • Several chained model calls need streaming and a time budget per turn.
  • Avoid services that bill while idle until load justifies them.
Exercise
Cost one 60-second request against a 5-second one on your platform.
Check
Why does a short wait plus polling beat one long call?
