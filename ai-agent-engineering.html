TL;DR

  • Seven boxes, with the orchestrator in the middle. The model is the easiest part to swap.
  • Workflows before agents. If you can draw the flowchart, build the flowchart.
  • Tool descriptions are prompt text. The tool's class decides control flow.
  • Code owns every write. Design for blast radius, not detection.
  • Most agents need working and episodic memory only. Context is a budget.

H3 Tool design and tool classes

P1 corePracticeNotesLesson

The model sees only name, description and schema. Write them like prompts.

  • A few purpose-built tools, namespaced, not one per endpoint. Anthropic
  • Return names, not opaque ids. Paginate and truncate by default.
  • Errors say how to fix the input. Parameters say user_id, not user.

Server-dispatchBackend runs it; a short closing turnSearch, list my items
Client-actionThe browser applies itChange the theme
Intent (confirm)A proposal; the user approves; the normal API runsDelete, share
DelegationAnother agent handles itAsk a critic agent
StaticCanned, no model call"What can you do?"

The confirm path calls the REST endpoint a human would. Authorisation lives in one place.

H4 Agent security: design for blast radius

P1 coreNotesPracticeLesson

You cannot detect every injection. Limit what a hijacked agent can do.

  1. Identity Resolved at the edge, carried through.
  2. Data boundary No training on your data, short retention, region pinned.
  3. Injection It arrives with the evidence: a ticket, a PDF, a tool description.
  4. Tool gate Reads allow-listed and scoped; writes behind approval.
  5. Audit Keep the retrieved document ids.
The lethal trifecta

Private data, untrusted content and a way out, in one agent. Never all three. Willison

Stored state that re-enters the prompt is untrusted. Validate it on read and on write. See OWASP LLM Top 10.

H6 Memory layers and context management

P2 depthNotesPracticeLesson

Context is an attention budget. Spend it on purpose.

Working

The current step, in memory.

Episodic

What happened, append-only.

Semantic

Facts and preferences, in a vector store.

Procedural

Prompts and tools, versioned.

  • Long tasks: compaction, notes outside the context, sub-agents. Anthropic
  • Compact past a turn threshold, and bill the summariser's tokens.
  • Keep task memory apart from what the assistant remembers about the person.

H8 Protocols: MCP and A2A

P2 depthPracticeLesson

MCP connects an agent to tools. A2A connects agents to agents.

MCP
JSON-RPC; the host asks consent before a tool runs. Spec
A2A
Agents discover each other through agent cards. a2a-protocol.org
Traps
A2A in one process is overhead. Cards must use the public URL.
