DevOps and CloudOps principles

Track F. Gate production on a recent real deploy and ship the tested image; treat IaC state as shared state; promote by library or GitOps knowingly; place agents by capacity model; roll out in reversible waves and canaries; know the network path; alert on symptoms against SLOs; run incidents with clear roles; troubleshoot in six steps; load-test for real; rehearse restores; talk unit cost.

TL;DR

  • Gate production on a recent real deploy to test. Ship that image, never a rebuild.
  • IaC state is shared state. Keep it remote and locked.
  • One change per wave, each with an exit test and a rollback. Roll back first.
  • Page on symptoms users feel, against an SLO. Spend the error budget on purpose.
  • Rehearse restores. Talk unit cost, not the monthly bill.

F2 Infrastructure as code

P1 corePracticeNotesLesson

Every tool that declares infrastructure is another state to reason about.

  • Keep state in a locked remote backend; it can hold secrets. Terraform
  • Never apply a restore stack together with the live stack it shares state with.
  • Look a resource up only when someone else owns it, and know who.
Review every plan for three things

Resources destroyed. Permissions widened. Data stores replaced.

Check

F6 Networking

P2 depthNotesLesson

Name source groups, not address ranges. Know what every hop costs.

Inside

  • Subnets across zones
  • Database port open to a named group
  • Private endpoints to regional services

CORS lessons

  • Preflight passes before auth
  • Gateway errors need CORS headers too
  • Same origin avoids preflight

Latency

  • ~0.5 ms in one data centre
  • 100–150 ms Europe to the US

F9 On-call, escalation and incidents

P2 depthNotesPractice

Clear roles, roll back first, and a blameless review after.

  1. Detect Most incidents follow a change: check deploys first.
  2. Triage By severity.
  3. Mitigate Roll back first.
  4. Resolve Then find the root cause.
  5. Review A blameless postmortem with tracked actions.

F10 Troubleshooting in six steps

P2 depthNotes

Turn a complaint into a measurement, then bisect the stack.

  1. Define A complaint becomes a number.
  2. Scope Who and what is affected.
  3. Bisect Client, DNS, CDN, balancer, app, cache, database, third party.
  4. What changed? Check the deploy timeline first.
  5. Measure Test the hypothesis.
  6. Fix and prevent Restore, then make it visible.
CaseCause

T2 Wrong numbers after a weekendLocal time across daylight saving
T3 Assistant got worseA bad re-index hurt retrieval
T4 Warehouse bill doubledAn unfiltered query every 15 minutes

F11 Load and performance testing

P2 depthNotesPractice

A smoke run proves the path works. It proves nothing about load.

  • Thresholds like p(95)<200 fail the run and can gate a pipeline. k6
  • One harness was fully written and never run. Run it, and keep the artefact.
Exercise
Run a spike profile against non-production and store the result.
Check

F12 Backup, restore and disaster recovery

P2 depthNotesPractice

RPO is the data you can lose. RTO is the time to recover. Rehearse both.

  • Snapshot before a risky change; restore automatically if it fails.
  • Reset credentials after a restore when the restore does not carry them.
  • A written procedure with an estimate is not a measured rehearsal.
Exercise
Write the RPO and RTO you would promise, and how you would prove them.
Check
Why is a credential reset part of the restore?

F13 Cost and FinOps

P2 depthPracticeNotesLesson

Inform, optimise, operate. Speak in unit cost. FinOps

  • Per tenant, per 1,000 requests, per agent turn, not per month.
  • Easy wins in code: a stopped warm pool, per-service log retention, expiring untagged images.
  • One AI product spent about 90% on images. A separate daily cap bounded the worst case.
Exercise
Compute one unit cost for a service you own.
Check
Why is a unit cost more useful than a monthly bill?
