TL;DR

  • RAG is two pipelines. Most "hallucination" is a retrieval miss: measure recall@k first.
  • Hybrid search, fused by rank, then re-ranked. More context is not better.
  • Evaluate cheapest first: checks, a golden set, a calibrated judge, online signals.
  • Do the cost arithmetic aloud. The first lever is not calling the model.
  • Uptime is not correctness. Pin model versions; run evals in CI.

H10 Retrieval quality

P2 depthNotesPractice

Was the evidence retrieved? Answer that before you touch a prompt.

−35%failed retrievals, contextual embeddings
−49%plus contextual BM25
−67%plus re-ranking

Published benchmark: Contextual Retrieval.

Chunking
Split on structure, keep the heading; 300–800 tokens, 10–20% overlap.
Hybrid
Vectors plus BM25, fused by rank (RRF, k = 60).
Re-rank
50–100 candidates down to 5–10.
Assembly
Models miss the middle of long context. Liu et al.
Metrics
recall@k first, then MRR, nDCG@k, context precision.

H11 Knowledge graphs

P3 referenceNotes

Vectors cannot do multi-hop, global themes or counts. Graphs can, at a cost.

  1. Graph as metadata Tags and links on chunks.
  2. Graph as retriever Walk the graph to find chunks.
  3. Graph as the knowledge Answer from the graph itself.
The hard part

Entity resolution. Design the schema first; check access on every hop.

H12 Evaluation: four layers

P2 depthNotesPractice

Cheapest first. Never stop looking at the data. Husain

  1. Deterministic checks Valid JSON, fields, real citations, latency. 60–70% of the surface.
  2. Golden set 50–100 cases grown from real failures.
  3. Calibrated judge Checked against human scores first.
  4. Online signals How much users edit a draft before sending.
Judges have biases

Position, verbosity, self-preference. Use pairwise comparison and a rubric. Zheng et al.

Exercise
Write ten golden cases from real failures and one deterministic check.
Check
Why calibrate a judge before trusting it?

H13 Cost and latency

P2 depthNotesLesson

Requests × tokens × price, aloud. Then pull the levers in order.

  1. Don't call the model Answer from a cache or from code.
  2. Cache the stable prefix The part that repeats on every call.
  3. Route by difficulty A small model first.
  4. Send less context Fewer, better chunks.
  5. Batch offline work When nobody is waiting.
  6. Cap output Output costs more per token.

Streaming improves time to first token, not total time. A short turn on a small model costs about a tenth of a cent.

Exercise
Cost one feature per 1,000 requests, then apply the first two levers.
Check
Why does streaming change what users feel but not what you pay?

H14 Model choice and the gateway

P2 depthNotesLesson

A gateway routes, pins versions, retries, falls back, caches and enforces quotas.

  • Small models route and extract.
  • Fine-tuning changes behaviour, not facts.
  • A model change is a config change plus an eval run.
  • Choose on the eval, the price and the terms, not on the cloud you use.
Exercise
List which steps of one feature could move to a smaller model.
Check
Why does fine-tuning not fix missing facts?

H16 AI agents in the engineering workflow

P2 depthNotesLesson

Machine agents run the system. AI agents change it. Neither does both.

Machine agents

Run the system; cannot change it.

AI agents

Declare what they may write. The worst run is a declined PR.

False approvals

A review agent approved bad changes, so its output is a comment, never a merge.

With coding agents: plan, then workers, then integrate. Freeze contracts first.

Exercise
Write the "may write" declaration for one agent you would build.
Check
Why is a comment-only review agent safe unattended?
