TL;DR

  • One record of truth at the centre. Every other path has a job relative to it.
  • Systems meet at APIs, never at each other's database.
  • The account is the boundary that contains a mistake. Subnets and tags only organise.
  • In a shared store, tenant isolation lives in the query. Identity comes from the token.
  • Default to boring technology. Production-ready is a checklist with evidence.

B2 Integrate through APIs, not shared databases

P1 coreNotesLesson

The seam between systems is an API with a contract. Data stays where it lives.

Through the API

  • The owner keeps authorising
  • Calls run as the user, with their token
  • Every call can be audited

Into the database

  • Couples to the schema
  • Bypasses authorisation
  • Leaves no audit trail

Move the small, stateless part to the data. Reporting needs get a read-only API over the warehouse.

Exercise
List every system that reads your database directly, and the API to replace each.
Check
What does a direct database read bypass?

B3 Accounts are the blast-radius boundary

P1 corePracticeNotes

No access crosses an account unless you allow it. So the account is what contains a mistake.

  • Shared non-production accounts are contained from production, not from each other.
  • A network looked up, not created, is inherited. Know who owns it.
  • AWS recommends several accounts, not one. AWS whitepaper
Exercise
For a mistake in one dev environment, list everything it can reach.
Check
Why is one pipeline-execution account good for audit?

B5 Tenancy: isolation lives in the query

P1 corePracticeNotes

In a shared store, the boundary is whatever filters every read.

  1. The token authorises The tenant comes from a validated claim.
  2. The path is a log field /api/{tenant}/… is never a boundary.
  3. Every read is filtered A hook adds the tenant to each query.
  4. Every call site counts A caller-supplied filter can skip the hook.
The cost of sharing

A noisy tenant slows every other tenant. A restore brings back all tenants or none.

Broken object-level authorisation is item one of the OWASP API Top 10.

Exercise
Test reading another tenant's record through a call site with its own filter.
Check
What happens to isolation when a caller passes its own filter?

B6 Choose boring technology

P2 depthPracticeNotes

Spend your few innovation tokens where the business is different.

  1. Measure Find the real bottleneck first.
  2. Cache, read replicas The cheapest relief.
  3. Scale out stateless More instances, no shared state.
  4. Queue slow work Take it off the request path.
  5. Partition data Only when one store cannot cope.
  6. Multi-region Last.

Each new tool costs the whole organisation, not only the team that chose it. McKinley

Exercise
List your service's technologies and mark which spent an innovation token.
Check
When is a new technology worth its token?

B8 Production-ready is a checklist with evidence

P2 depthNotesPractice

Each tick needs its evidence, and whether it came from config or from a person.

Foundation

  • Production alone in its account
  • Customer-managed keys
  • Three scanners per merge
  • Only the tested image ships

Platform

  • Two availability zones
  • A tenant filter on every read
  • Malware scan on upload
  • Snapshot and auto-restore

Data pipeline

  • At-least-once, idempotent upserts
  • Retries, then a dead-letter queue

Company

  • ISO 27001, a recent pen test
  • On-call with runbooks, an SLA

Cross-check against the six Well-Architected pillars.

Exercise
Tick the list for one service you own and attach evidence to each tick.
Check
Which ticks come from config, and which rest on someone's word?
